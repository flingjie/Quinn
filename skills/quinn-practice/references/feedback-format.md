# 每轮反馈格式

固定四要素，默认一次只处理一个关键缺口：

1. **引用**用户尝试中的一处具体内容（原文，不概括）。
2. 说明它为什么有效，或与目标存在什么**缺口**。
3. 给一个**可执行修改动作**。
4. 留一个小练习或下一步，允许用户**跳过**。

需要多种思路时最多给三种，并各自说明用途，避免连续追问让用户无法推进。

## 诊断 vs 标签

诊断呈现为「基于本次样例的待验证判断」，不凭一次表现贴能力标签。区分：知识不足 / 方法不熟 / 情境信息不足 / 时间受限 / 表达困难。

## 反馈状态与依据

- `verdict`：`demonstrated` / `needs_work` / `insufficient_evidence`。
- `demonstrated` / `needs_work` 必须带 `source_quote`（引用原文）；`insufficient_evidence` 合法无引用。
- 模型评价是建议性反馈，用户可纠正：保留原判定与纠正，不静默覆盖。
- 不能用模型自报置信度代替验证，不能用单次业务结果反推能力。
- 反馈指向判断过程而非结果对错（复用 `mentor-interaction.md`「反馈按任务类型」：是否预先陈述假设、是否识别未知、是否提出能区分的验证动作）。
