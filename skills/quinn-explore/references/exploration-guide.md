# 探索指引（按需加载）

内部判断用。不要把卡点表当分类器结果展示给用户，也不要宣布“你现在处于某某卡点”。

## 卡点 → 下一步（单一缺口）

缺口是暂定解释，可被用户纠正；每次只处理一个最影响进展的缺口，不一次诊断全部。

| 缺口 | 可观察信号 | 优先引导动作 | 结束或转向条件 |
| --- | --- | --- | --- |
| facts | 只给评价，缺少事件 | 请求一个具体发生的例子；转 `quinn-research` 核查 | 事实足以回答时直接结束 |
| framing | 多个问题混在一起 / 表达过度抽象 / 目标冲突 / 尺度过窄 | 明确当前要决定或解释的事；读 `reframing-operators.md` 识别判断结构、选一个算子 | 找到有意义的替代理解或澄清问题 |
| alternatives | 只有单一解释且尚无充分支持 | 邀请一个机制不同的解释；给 1–3 个实质不同的方向（种子） | 用户选定方向或证据排除解释 |
| evidence | 判断缺依据，或把相关当因果 | 区分事实与解释，找能区分假设的证据；转 `quinn-research` | 有可区分假设的证据，或承认暂时不可分 |
| tradeoff | 方案齐全却无法选择 | 明确目标、约束与取舍标准（可读 `shared/methods/unit-economics.md` 等） | 按标准可比较，或用户保留探索 |
| action | 判断清楚却没有可行下一步 | 缩小验证范围与成本（接行动复盘路径） | 得到一个最小下一步或暂缓条件 |
| transfer | 只能复述原例 | 换条件或场景，检查机制与边界（邀请一次迁移动作） | 能说明共同机制与不能照搬的边界 |

多种缺口并存时先处理阻碍下一步的一个。原判断合理不是缺口，作为终止态：补条件或支持证据后无实质缺口即自然结束。

### 重映射对照（旧 6 卡点 → 7 缺口）

| 旧卡点 | 去向 |
| --- | --- |
| 缺事实 | facts |
| 现象无法解释 | alternatives + evidence（给不同解释 + 找证据区分） |
| 默认只有一种方案 | alternatives |
| 零散想法难连接 | framing |
| 类比有趣但空泛 | evidence |
| 原判断合理 | 非缺口，终止态 |

新增 tradeoff / action / transfer 三行。原 explore SKILL 步骤 4 的「reframing 分支」并入 framing 缺口的引导动作，不再单列。

## 种子（不同方向）

探索开放问题时通常 2–3 颗；问题明确时可 1 颗。每颗用 2–3 句话说清：不同的解释或问题、借用的机制、可能改变什么。详细证据和映射在选中后展开。

发送前检查：

1. 选择不同种子，是否真的会导向不同的解释、问题或行动？
2. 是否只是换了行业名称，实际建议相同？
3. 是否相关且可讨论，而不只是令人惊讶？
4. 真实案例是否有依据，纯假设是否标明？

未达到差异要求时合并种子，不再搜索材料凑数。用户要求“更远一点”时扩大领域距离，保留与原问题的关系。

## 回看后的方向取舍

synthesize 把「定下一阶段方向」交给 explore 时，比较 2–3 个**实质不同**的方向，各自说清：回应什么问题、依赖什么条件、放弃什么、什么证据能改变选择。不套评分、不强制目标设定；只有一个方向真实时就说一个。候选方向不等于用户目标，确认后才标记「用户选择」。

## 迁移动作（每次最多一个）

选中方向并理解机制后，在合适时邀请：

- “放到你的项目，你会先改变哪一处？”
- “如果这个解释成立，你预计会看到什么？”
- “这个机制在哪种情况下会失效？”

用户已主动迁移就直接接着讨论；要先听示例时可先演示；只想获取资料时不插入练习。没有真实项目可以换到一个相邻情境。不要把选择种子等同于认可结论，也不要先写完整答案再让用户复述。

## 发散与收敛

- **发散：** 允许大胆假设，暂存待验证项；涉及事实的主张仍需核查。用户要求继续发散时不急于否定。
- **收敛：** 优先检查一个决定性假设——机制的因果关系、目标情境缺少的条件、最有力反例，或会让我们放弃的证据。发现缺口可回到 research 或继续探索。

不要求一次探索同时完成反转、类比、组合、实验四种动作。

## 质量合同

### 前提反转

必须说清：原前提是什么、改变什么条件、何种情境下反转可能成立、打开了哪种新选择。不能仅将“应该”改为“不应该”。用户不认可原前提时先修正理解。

### 机制重组

必须说清：每个机制解决哪个子问题、通过什么信息或行为衔接、依赖条件是否冲突、重组后方案有什么具体变化。不要求每次强制拼接两个机制。

### 跨域迁移

展开时检查：原领域机制、目标对应、缺失条件、失效例子。如果只有表面相似，称为比喻，停止把它当产品依据。科学机制用于商业时，区分原领域依据与目标迁移假设。

### 框架转换

必须保留用户原判断与 Quinn 的候选重构之间的区别。转换后说明改变的是定义、范围、证据标准、目标优先级还是观察尺度，并指出它新增了什么可检验差异。不能把正面措辞当成改善，也不能连续套用多个模式把用户带向预设答案。

## 自然结束

按实际发生留下：新认识、开放问题、被确认的原判断，或尚无变化。用户想推进时再形成机会假设和最小实验。记录变化必须依据用户表达；模型总结尚未经用户表达支持时标为 Quinn 的候选总结。

### 分类结束（按问题类型）

结束摘要由 synthesize 产出，按问题类型对应可接受的结果；用户明确表示足够时允许结束，不作必答仪式：

| 问题类型 | 可接受的结束结果 |
| --- | --- |
| 概念理解 | 用户能重述并给出例子或反例 |
| 判断分歧 | 明确依据及什么证据会改变判断 |
| 实际选择 | 得到决定、下一步或暂缓条件 |
| 创意探索 | 留下一个有价值的方向及其理由 |
| 实践复盘 | 修正判断或适用边界，也允许证据不足 |
