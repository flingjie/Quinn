# Quinn 行为场景与试用对照

日期：2026-09-12  
用途：P0 对照基线 + P1–P3 人工验收。认知质量靠对话评审，不靠关键词匹配。

## 三个真实困惑（对照用）

未表达的原先理解不补造基线。

### A. 开放探索

**困惑（用户原话风格）：**  
「很多产品加了 Agent，但用户还是坚持手动确认每一步。是不是信任没建立起来？还是其实用户根本不想把控制权交出去？」

**覆盖：** 现象无法解释 / 可能有多种机制；适合给不同方向。

**旧版输出摘要（改造前 quinn-explore 行为）：**

- 默认按 AI 产业讨论切入，容易先谈信任、验收、按结果收费等熟悉框架。
- 会邀请补充理解或选择方向，但较少先识别卡点；也可能一次铺开多个分析维度。
- 结束倾向保存 `discussions`，收尾交给 synthesize 写 `insights`，不一定区分“用户已表达的变化”与“Quinn 候选总结”。
- 未明确要求时也可能提到机会假设；缺少“用户自己迁移”的可选小动作。

### B. 事实缺口

**困惑：**  
「OpenAI 最新一次公开的 ChatGPT 周活用户数是多少？我只想核实这个数，别展开。」

**覆盖：** 只缺一个事实；应查证直答，不硬塞跨域类比。

**旧版输出摘要：**

- research 会先 `find` topics/insights，再拆子问题、给讨论方向。
- 即使“只核实一个数”，步骤仍偏向产出可讨论材料与 2–3 个方向，容易过度展开。
- 来源规则健全（URL、访问状态、归属），但缺少“选择前最低核查 / 事实足够即结束”的明确出口。

### C. 不适合强行跨域

**困惑：**  
「我们团队周会总是超时，有人觉得该砍议题，有人觉得该改成异步更新。这就是个协作问题，别硬往 AI 或别的行业扯。」

**覆盖：** 完全非 AI / 原领域即可；不强行跨域。

**旧版输出摘要：**

- Skill 描述锚定 AI 产业，容易把协作问题拉回 Agent/自动化叙事。
- 方法库多为单位经济、价值链等，缺“留在原领域、指出类比不足即停”的硬规则。
- 讨论记录仍走 discussions → insights，不以 session 记录理解变化状态。

## 框架转换试用记录（v3 验收）

对三个真实困惑跑框架转换（`reframing-operators.md`），验收「该触发就触发、不该触发不硬套」。

### A（开放探索，现象无法解释）

- 框架转换：**跳过**。卡点=现象无法解释，不在「过度抽象 / 绝对化 / 目标冲突 / 尺度太窄」四类内，直接给三颗种子（授权阶梯 / 责任锚点 / 决策成本），不硬套算子。
- 隐含判断「手动确认=不信任」（X 是 Y）仅作内部可纠正标记，未向用户暴露。
- session `a3b5f653e08d46f094209448de4c23ea`，`change_status=unconfirmed`。

### B（事实缺口）

- 框架转换：**跳过**。卡点=缺事实，按「何时使用」直接转 research 最低核查，未硬塞重新定义 / 改变尺度。
- 来源两次检索均不可用 → 标 `access_status: failed`，不伪造数字。
- research `bdce43a75b3347f7982c5063244a82f3`，session `9a17b103583f47eb9a13b14ed2701791`，`change_status=no_change`。

### C（目标冲突，非 AI 协作）

- 框架转换：**触发**。识别「应该砍议题 vs 应该改异步」两个规范判断 → 选「准则层次」算子 → 过证据闸门（明确「信息同步 vs 讨论质量」的评价标准）。
- 留在协作域，未跨域，未暴露算子术语，未替用户决定优先级。
- session `f5ed768bf85f478cb5d4dbd3572722e4`，`change_status=unconfirmed`。

验收结论：三例中框架转换只在目标冲突（C）触发，且产出可检验的标准差异而非换措辞；事实缺口（B）与现象无法解释（A）正确跳过，未硬套。与方案 §3.2 / §5 / §10 一致。

## 周期性回看验收（P1）

样本：现有 6 份 session 均 `2026-09-12`，可用于「2026-09-01~2026-09-30」窗口；用 `find "" sessions --since 2026-09-01 --until 2026-09-30` 取候选。

| 场景 | 预期结果 |
| --- | --- |
| 有三个月讨论，用户仅要总结 | 只总结有证据的变化与未知，附会话定位，不追问目标 |
| 讨论稀疏，要求「全面人生回顾」 | 标出覆盖缺口，邀请补充必要领域，不编造 |
| Quinn 提出「你害怕公开表达」 | 作为待确认解释或删掉，不记录为用户心理事实 |
| 用户反对某条归纳 | 保存纠正原文并更新回看；不把旧归纳继续当定论 |
| 用户未选择下一阶段方向 | 候选仍为候选，不生成已确认年度目标 |
| 只有一个新事实依赖外部资料 | 仅查证关键事实并标记来源与时效（转 research） |
| 重复生成或并发修改回看 | 不重复建档、不静默覆盖用户修订（沿用 revision 冲突） |
| 用户要求一年后回访 | 记录回访条件；无定时能力时说明需用户再次发起 |

代码测试聚焦检索范围（`find --since/--until`）、引用完整性（`record_ids` 指向源会话）、归属与版本冲突；认知输出用真实样本人工检查：是否误判成长、是否强行改判、方向是否真不同、交互是否过重。
