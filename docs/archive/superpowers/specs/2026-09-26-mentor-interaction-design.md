## 1. 背景与现状核查

本设计源于《Quinn 导师式交互调整实施计划》（`Downloads/Quinn-Mentor-Interaction-Implementation-Plan.md`，下称「导师计划」）。该计划标注"尚未核查 Quinn 仓库"，并假设"不能断定仓库已经有三个 Skill、会话记录或检索能力"。

实际核查结果：**该假设已过时。** 仓库已完整实现：

- 三个 Skill（`skills/quinn-explore|research|synthesize/SKILL.md` + 参考文件）。
- 会话主记录（`workspace/sessions/`，7 份），含 `change_status`、归属分离、「当前理解」分用户表达 / Quinn 候选、「纠正与修订」。
- 检索与周期回看 MVP（`find --since/--until`，commit `c04672a`）。
- 框架转换算子 + 证据闸门（v3，commit `963a32a`）。
- 产品契约已强制「AI 提议不得经默认值变成用户已接受」「不替用户决策」「不制造成长」。

因此导师计划的大部分 P0（核查仓库）已完成，真正的工作是**在 `quinn-explore` 上叠加一层行为标准**，而非新建基础设施。

## 4. 核心规则（写入 `mentor-interaction.md`）

1. **内部决策顺序**：识别意图与卡点 → 判断依据够不够 → 先给判断/建议还是先查事实 → 只在有分支价值时问一个问题。简单事实直答；纯整理/只保存不开启导师问答；信息不足但可前进给条件化建议；只有关键歧义阻断下一步才先提问。
2. **「四件事」是内部检查，不是固定模板**：暂定判断（标明事实 / 基于材料的解释 / 未证实假设）+ 依据与边界（依赖什么、缺什么、什么反例改判）+ 建议与代价（"倾向 X 因 Y，代价 Z，出现 W 则改选"；有实质不同路径再给一条替代）+ 一个决定性问题（说明不同答案如何改建议）。
3. **建议的安全线**（对齐产品契约）：建议是「有代价、可证伪、条件化」，不是替用户拍板；决策权始终在用户；未请求推进执行就停在更清晰的问题或解释；不把 Quinn 建议写成用户决定。
4. **五态支架表**（沿用导师计划 §3）：

   | 可观察状态 | Quinn 的动作 | 应避免 |
   | --- | --- | --- |
   | 用户已有明确判断和依据 | 指出最重要的边界、反例或第二阶影响 | 重讲基础概念、机械反驳 |
   | 用户有几个方向但难取舍 | 明示评价标准和各方向代价，先给倾向 | 罗列等权选项后把决策全交回用户 |
   | 用户卡住，缺少切入点 | 示范一次拆解，给一条可修正的候选解释 | 空泛地问「你怎么看」 |
   | 用户已有清晰问题，只缺事实 | 调用 research 补事实，然后直接回答 | 为显得像导师而强行追问 |
   | 用户纠正 Quinn 的推断 | 复述修正后的理解，更新建议 | 为保留原结论继续辩护 |

   状态只依据当前表达与可追溯记录，不推断能力等级、性格或隐藏动机。

5. **问题分支价值检查**：发问前内部写至少两种回答及各自不同下一步；无差异就删问题直接给建议。一次回复最多一个主要问题；用户回答后先吸收、再说建议如何变；可跳过或反驳前提。
6. **纠错后改判**：用户否认时复述修正后的理解、更新建议；不把否认解释成「更深层证明」；记录修订、不覆盖旧版本。

## 5. 记录增量

`session-format.md` 加两个可选正文小节（空则省略）：

- 「导师判断与依据」：Quinn 的候选洞察、引用依据、替代解释及信心的文字边界（对应导师计划 `mentor_hypothesis`）。
- 「建议与代价」：建议、主要代价及改判条件（对应导师计划 `recommendation`）。

复用现有小节：`pivotal_question` → 「开放问题」；`user_response` / `revision` → 「纠正与修订」+ `change_status` / frontmatter `revision`。只记实际发生，不为每轮补齐字段。

## 6. 反模式与硬失败

写进 `mentor-interaction.md`：伪造洞察、把候选写成用户立场、替用户决策、逢问必追、建议太多、明知事实不足仍自信下结论。保存失败不报成功（沿用 `scripts/workspace.py` 现有机制）。

## 7. 测试与验收

- 交互质量靠 `evals/scenarios.md` 真实样本人工对照 + 内部 0/1/2 五维 rubric（洞察增量 / 依据归属 / 建议取舍 / 问题分支价值 / 吸收反馈改判），只用于版本对比。
- 代码层面无需新增测试（无 schema/脚本改动）；跑一次 `python3 scripts/workspace.py selftest` 确认未破坏现有写入。
- 三段固定真实样本（Quinn 定位 / Finch 连接者策略 / 一次跨域迁移）做首轮回应前后对比。
