# Quinn 实施计划：商业与产品判断训练 MVP

版本：v4 · 第一性原理简化版  
日期：2026-09-10  
依据：v3 融合方案及本轮评审结论。此文件为新的实施基线；未执行代码修改或 Skill 安装。

## 1. 唯一核心目标

让用户面对一个新问题时，主动找到影响选择的关键因素，并说明自己的选择在什么条件下成立。

商业与产品共同构成练习情境。MVP 要验证：一次具体挑战能否帮助用户理解此前遗漏的关系，以及用户之后能否在陌生情境中主动使用该关系。

当场改好答案是提示后表现；延迟新题中的独立表现才提供迁移证据。少量案例仅用于发现学习迹象，不证明训练的因果效果。

## 2. 本轮实施决策

| 项目 | 决策 |
| --- | --- |
| 交互 | Codex GUI，自然语言多轮对话 |
| 入口 | 一个 business-judgment-practice Skill，展示名 Quinn |
| 内容 | 四题、两组基础与迁移练习 |
| 产品融合 | 在同一流程中加入产品情境，共用记录和反馈 |
| 训练目标 | 每题一个具体、可观察的判断动作 |
| 六维分类 | 商业逻辑、成本、风险、利润、用户问题、方案取舍仅作内容标签 |
| 挑战 | 默认一次具体挑战；卡住时允许明确教学帮助 |
| 反馈 | 本题分数、原文证据、一个改进点 |
| 等级 | 按具体能力给暂定描述，不实现六维等级面板 |
| 存储 | 一题一份 JSON；案例采用 Markdown 文件 |
| 时长 | 默认约 10–15 分钟，可暂停，不硬计时 |

本轮不实现八题全覆盖、动态课程、独立产品 Skill、数据库、Graph Runtime、独立 LLM 服务、自动报告、自动等级升级或定时推送。

## 4. 四题启动包

| ID | 情境 | 可观察的学习目标 | 关系 |
| --- | --- | --- | --- |
| case_001 | AI 报告服务中的人工交付 | 主动识别随客户量增加的人工投入，并据此判断推进条件 | 商业基础题 |
| case_004 | 软件实施与持续维护 | 在新情境中主动识别随规模增长的交付投入 | 001 的延迟变式 |
| case_005 | 用户要求增加看板 | 区分功能请求与实际任务，并据此决定下一步 | 产品基础题 |
| case_008 | 团队要求增加提醒 | 在新情境中区分请求方案与实际协作障碍 | 005 的延迟变式 |

每题自然加入必要的用户价值和经营约束，不设置独立“融合题”流程。四题只验证两类关系，不宣称覆盖全部商业或产品能力。

### 4.1 题面要求

brief.md 必须包含：教学模拟或真实改编标记、决策目标、资源约束、已知事实与数字、关键未知项、行动问题。

基础题提问：“你会怎么选？主要依据是什么？什么条件会改变你的选择？”

复测题只问：“你会怎么选？请说明依据。”不展示学习目标、关联原题、能力标签或检查框架。

默认把目标和主要约束放在题面。若刻意缺少目标，学习目标必须明确为“识别目标不清并澄清”，不能事后用新增目标判初判错误。

### 4.2 教练文件要求

coach.md 包含：

- 一个学习目标及其可观察证据。
- 题目中的事实、教学假设与未知信息。
- 至少两条可接受的推理路径；条件不同可作不同选择。
- 本题 0–4 分锚点，以及少量短回答示例。
- 常见遗漏和一条少提示的挑战示例。
- 什么情况应停止挑战、直接反馈。

优先采用人工精选、核实过的真实材料改编。没有合适材料时使用明确标记的教学模拟；不编造来源、用户访谈或真实经营结局。本轮无需 outcome.md。

### 4.3 题目验收

信息足以支持有条件的判断；单位一致；存在真实取舍；无需大量行业知识；题面不暗示目标答案。变式必须更换表面情境，同时保留关键关系，不能只是替换公司名称与金额。

## 5. Skill 行为协议

### 5.1 自然语言入口

| 用户意图 | 行为 |
| --- | --- |
| 今天练一下 | 续练或按索引选题 |
| 今天练产品／商业判断 | 在对应主题中选题 |
| 继续上次 | 读取未完成记录，继续缺失的步骤 |
| 复盘最近的练习 | 对照初判与后续证据，给暂定能力描述 |

### 5.2 训练步骤

1. 选题，建立 Session；只读取题面并展示，然后等待用户。
2. 收到初判，立即原样保存，再读 coach.md。
3. 找到最可能影响选择的推理缺口，提出一个具体挑战；保存后展示，等待用户。
4. 收到后续回答，原样保存。合理坚持和修正均可。
5. 给出简短反馈并保存，标记完成。
6. 后续遇到符合条件的陌生变式，先收集独立初判，再进入教学。

若初判已充分覆盖目标，不强行挑错，可直接反馈。用户请求解释或仍卡住时允许补充明确教学，不反复盘问；用户希望暂停时保留现场。不得模拟用户回答或自行跑完多轮对话。

### 5.3 挑战设计

默认提供最少必要提示，引用用户原话，针对一个推理缺口提问。

例如，用户说“收入减工具费还剩九千”，先问：“拿到这九千元，需要你每月投入多少工作？”避免第一步就给出完整成本答案。

挑战有三种含义，反馈必须区分：

| 类型 | 观察对象 | 不能声称 |
| --- | --- | --- |
| 检查原推理 | 原目标和事实下是否存在遗漏 | 用户一改答案就说明已掌握 |
| 新增事实 | 是否根据新证据合理更新 | 原判断必然错误 |
| 改变目标或约束 | 是否理解行动对条件的依赖 | 新选择证明原选择错误 |

无需为三种挑战创建引擎或独立模块，实际提示文本和反馈说明足以保留依据。

## 6. 评分与等级

### 6.1 分数

每题只按该题目标评 0–4 分；不足以判断时为 null 并说明原因。通用锚点仅辅助解释：

| 分数 | 含义 |
| --- | --- |
| 0 | 信息足够时，出现与本题目标有关的关键误判 |
| 1 | 提到相关变量，但未建立影响选择的关系 |
| 2 | 识别核心关系，并用于解释选择 |
| 3 | 正确使用关系，同时说明重要条件或未知项 |
| 4 | 在本题需要的范围内，检验关键边界并作出证据相称的判断 |

高分不要求长篇回答、不要求覆盖六维、不奖励术语数量。用户未选择教练偏好的选项不能成为扣分理由。每个非空分数至少有一条对应阶段的原文证据；不能引用 AI 的措辞冒充用户能力。

分别展示初判分与提示后分。若没有后续回答，提示后分为 null。新增事实或改变目标时，明确两次回答的条件不同，不把分差当作进步量。

### 6.2 暂定能力描述

保留用户期望的等级反馈：L0 直觉判断、L1 提示下识别、L2 独立分析、L3 假设驱动、L4 结构迁移。

等级仅针对具体能力，例如“识别规模化交付成本”，按实际原文证据判断，不由平均分计算，不强制覆盖所有等级。L4 需要多个陌生情境的独立证据；启动包只有一次变式成功时写“出现一次迁移迹象”，不宣布稳定掌握。

### 6.3 默认反馈

约 200–400 字，包括：已经抓住的点；本轮变化或合理坚持；初判和提示后分数及证据；下一次一个建议。阶段复盘再提供等级，避免每题都重复升级判断。

## 7. 最小记录格式

每题一份 JSON，保存无法重建的原始证据。主题从案例索引读取；能力总结按需生成，不维护能力数据库。

```json
{
  "schema_version": 1,
  "id": "session_20260910_001",
  "case_id": "case_005",
  "case_revision": "v1",
  "started_at": "2026-09-10T10:00:00Z",
  "completed_at": null,
  "stage": "awaiting_initial",
  "mode": "practice",
  "transfer_from_session_id": null,
  "initial_help": "none",
  "turns": [],
  "feedback": null
}
```

turns 按发生顺序保存 role、kind、text；kind 可为 initial、challenge、help、response、clarification。它是实际对话证据，不另建多套初判、更新和提示日志。第一条 initial 即冻结的初判；后续补充追加，不能覆盖。

feedback 包含 initial_score、assisted_score、evidence、next_focus；每条 evidence 引用具体 turn 序号及原文。复测时附简短 transfer_note，说明是否主动识别目标关系及证据限制。

initial_help 取 none、provided、unknown，表示初判前有无教学帮助；正常基础提问不算教学帮助。复测受到提示时标 provided；后续挑战不能反向修改初判时的状态。mode 取 practice、transfer、repeat。

stage 仅用 awaiting_initial、awaiting_response、completed。恢复时同时检查 turns：已有初判但尚无挑战，继续处理初判；已有后续回答但无反馈，继续反馈，不要求重答。

### 保存要求

- 收到用户内容后先保存原文，再生成后续分析。
- 挑战保存成功后再展示；同一 Session 重试更新同一文件。
- 保存失败说明情况，保留当前内容用于重试，不声称成功。
- 初期直接写 JSON，检查可读性、原文和关键字段即可。
- 发生真实保存摩擦后，再补原子写入与结构校验的小脚本。

schema_version 只描述本版结构；实施时若仓库已有同版本的不同结构，使用新的未占用版本号。旧格式只读兼容，不批量改写。无法恢复旧提示状态时标 unknown，不能计为无提示证据；旧评分不按新规则追溯覆盖。

## 8. 选题与复测

cases/index.json 只需 id、title、revision、tags、role、transfer_of、order。tags 可交叉；role 为 practice 或 transfer。

优先级：用户明确指定 → 继续未完成训练 → 符合间隔要求的未见变式 → 未做基础题。多个未完成训练时展示题名让用户选择。用户指定新题时保留旧训练，不强制完成。

默认基础顺序为 001、005。关联变式需跨过一个自然日，且其基础题后完成过至少一次其他训练；例如首日完成 001、005，次日可先做 004，再安排 008。用户每次只做一题也可，按实际使用推进。

间隔规则是低成本默认，不是最佳学习间隔结论。需要观察约一周保留时，后续补充另一道未见变式；不拿同题重复作答作为陌生迁移。

独立迁移证据需要：用户未见该变式；初判前未得到目标关系的教学提示；初判主动识别关系并解释其如何影响选择。条件无法核实时说明 unknown。新会话可以降低旧反馈的上下文影响，但不保证模型不知道关系，也不强制用户换会话。

题库用尽时说明没有新题；用户可重练，标 repeat，不自动编造未经审核的新题。

## 9. 实施任务与依赖

### P0：核查现状并确定本轮范围

- 阅读仓库实际说明与已有 Skill、案例、Session。
- 核对四个案例 ID，保留现有文件和历史身份。
- 标记已有实现与待实现项；以本文件替代旧方案中八题、六维等级面板等要求。

产物：README 中的当前范围及任务状态。验收：不把计划当实现，不删除无关资产。

### P1：制作两组案例和评分锚点

- 编写或修订四份 brief.md、四份 coach.md 和 index.json。
- 先明确学习目标，再编题；为每题提供不同合理结论的推理示例。
- 人工核查事实标记、数字、约束、变式关系和题面泄露。

验收：每题只检查一个可观察动作；两组变式既同结构又不同情境。P1 完成后进入真实教学验证，不先补其他四维题目。

### P2：实现单 Skill 闭环

- 编写 SKILL.md 与两个参考文件。
- 实现自然语言入口、明确等待点、少提示挑战、必要教学和反馈。
- 初判后才读 coach.md，不批量扫描所有题目。

验收：一次商业训练和一次产品训练均可走通；不替用户作答；不强行挑战；不同结论按推理评分。

### P3：实现记录、恢复与复盘

- 分阶段写入最小 Session，保留逐轮原文。
- 按已有记录恢复，不覆盖原回答。
- 复盘时按具体目标汇总独立证据与提示后证据。
- 存在旧记录则落实只读兼容；无旧记录则不预建迁移框架。

验收：中断后能继续正确步骤；重复保存不重复计数；分数都有原文出处；提示状态未知不当作 none。

### P4：人工验证交互风险

| 检查场景 | 通过标准 |
| --- | --- |
| 初判前求助 | 允许帮助，记录 provided |
| 用户合理坚持 | 不因未改答案扣分 |
| 初判已充分 | 可以直接反馈 |
| 用户卡住 | 明确教学，不机械追加盘问 |
| 挑战改变目标 | 不把条件变化当原判断错误 |
| 短但充分的答案 | 不因长度或术语少降分 |
| 保存或生成中断 | 原文保留，恢复缺失步骤 |
| 已见题重练 | 标 repeat，不计陌生迁移 |

优先使用少量人工对话。只有添加保存脚本后，才对无效覆盖、写入失败和重复记录补必要测试；不搭通用评测平台。

### P5：真实训练与延迟验证

- 完成两道基础题，观察挑战是否命中真正遗漏、反馈是否可解释。
- 满足间隔后完成两道变式，先冻结初判再教学。
- 给出一次证据式复盘，说明已观察到什么、什么仍无法确认。

验收：能区分独立识别、提示后理解、条件改变后的更新和重练熟悉度。没有出现迁移时如实记录，不能用完成次数或分数上升替代。

## 10. 调整规则与扩展门槛

| 实际现象 | 优先调整 |
| --- | --- |
| 用户只复述 AI | 减少首轮提示，检查变式是否真正陌生 |
| 产品题总答“先访谈” | 要求说明访谈需区分的具体假设，修订题目锚点 |
| 分数争议大 | 用争议原文修评分解释，不增加综合指标 |
| 一题总要长篇分析 | 缩小目标、删去无关数字与问题 |
| 两组均有独立迁移迹象 | 按真实薄弱点增加一个目标及其变式 |
| 保存经常出错 | 增加最小保存脚本 |
| 仅获得案例知识，判断无变化 | 修案例和挑战；持续观察后重新评估定位 |

不以完成次数自动扩建。六维能力体系、自动选题和独立策展入口，都等待实际使用需求与稳定证据。

## 11. 完成定义

- 一个 Skill 在 Codex GUI 中可用，商业与产品共用流程。
- 四题、两组迁移案例通过人工审核。
- 初判、实际提示、后续回答、分数证据可保存和恢复。
- 单题目标具体，评分不奖励长篇或迎合 AI。
- 至少走通商业基础题、产品基础题、一次中断恢复、两次延迟变式及一次阶段复盘。
- 复盘能诚实区分独立表现、提示后表现和证据不足。

前五阶段的功能验收与学习效果分开记录：系统可用不等于训练有效。后续投入以新情境中的独立判断变化为依据。
