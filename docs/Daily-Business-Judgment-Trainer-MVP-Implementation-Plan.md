# 每日商业判断训练器：完整实现方案

版本：v2 · 简化实施版  
日期：2026-09-10  
交互载体：Codex GUI；核心实现：一个 Skill + 案例文件 + 训练记录

## 1. 产品目标与验证假设

帮助技术型构建者在信息不完整时，判断一门生意是否值得推进，理解商业逻辑、成本、风险和利润，并说明什么证据会改变自己的选择。

MVP 要验证的最小假设是：用户独立判断时遗漏一个重要变量，经过一次具体挑战后理解它，之后遇到不同情境时能主动使用它。

当场修改答案表示本轮有所理解；之后无提示主动使用，才是更强的学习迹象。少量训练不能证明因果关系，也不以真实商业结局判断用户对错。

首批使用场景是个人日常练习。默认每次约 10–15 分钟，不做硬计时；用户可以暂停。先围绕 AI、软件和技术服务业务，之后再尝试跨行业题。

## 2. MVP 范围

必须实现：

- 用户先独立判断，AI 等待回答后再反馈。
- 一题一个主要训练目标；一次最多一个实质挑战。
- 保存初判原文、挑战、更新原文及证据反馈。
- 每次只评主练维度，分数有原文证据。
- 在后续训练中安排变式题，观察无提示表现。
- 用户请求复盘时，结合记录给出暂定能力等级与证据。

暂不实现：自动抓取案例、动态课程引擎、挑战候选筛选管线、自动等级升级、多个独立 Skill、数据库、通用 Graph Runtime、独立模型调用服务、排行榜和自动商业报告。

“每日”代表使用节奏，不代表第一版必须自动推送或定时运行。用户自己的 Idea 分析后续可复用训练方法，本版先围绕精选题验证。

## 3. 核心设计原则

1. 先作出选择，再展开分析。
2. 商业逻辑、成本、风险和利润是教练检查视角，不是每次必须填写的表单。
3. 一次只抓一个真正影响选择的问题，不强行找错。
4. 改变观点和有依据地坚持都可以是好表现。
5. 用户原回答是证据，AI 总结不能替代它。
6. 训练效果不明确时，优先改题目和挑战，不增加系统功能。
7. 事实、教学假设、反事实与未知信息必须区分。

## 4. 单次训练流程

| 步骤 | 用户看到什么 | Skill 做什么 |
| --- | --- | --- |
| 选题 | 今天的一道题 | 指定题优先；否则按简单规则选择 |
| 初判 | 背景、数字、待决策问题 | 等待用户回答，不提示关键遗漏 |
| 挑战 | 一条引用原回答的具体问题 | 找到一个可能改变选择的假设 |
| 更新 | 用户坚持、修正或暂缓及理由 | 保存原文，不要求认同 AI |
| 反馈 | 证据、主维度分数、一个改进点 | 比较初判与更新，区分提示前后表现 |
| 可选复盘 | 已核实的真实结局 | 反馈完成后才读取独立结局文件 |

### 4.1 初判交互

基础练习只问：

> 你会怎么选？最主要的依据是什么？哪个条件变化会让你改变选择？

允许自然语言，无需 YAML、枚举值或规定字数。不强制填写信心度和利润区间。题目涉及利润时，要求注明时间单位、主要假设并给出粗估；信息不足时可以给条件判断或提出小规模验证。

变式复测只问：

> 你会怎么选？请说明依据。

不提前展示训练目标、之前的薄弱点或结构标签。用户要求帮助时可以提供，但记录为已提示，此次不能作为无提示迁移证据。

### 4.2 挑战规则

Skill 只需要执行：

> 引用用户回答，找出其中最值得验证、且可能改变选择的一个假设，提出一个能在本轮回应的具体挑战。

推荐形式：

> 你提到“[用户原话]”。这里取决于 [关键假设]。假设 [明确标记的反事实或边界条件]，你还会作出同样的选择吗？为什么？

要求：

- 使用题目已知信息、用户陈述或明确标记的假设。
- 缺乏证据不等于假设已经被证明错误。
- 用户若已覆盖题目主目标，可检验边界；没有有价值的挑战则直接反馈。
- 不生成或保存挑战候选列表、淘汰原因、排序分数。
- 用户只是问题意不清时，允许澄清；澄清不等于追加一轮教学挑战。
- 不因用户拒绝 AI 建议而降分。

### 4.3 反馈格式

默认控制在约 200–400 字：

1. **你已经抓住的点**：引用初判及解释。
2. **本轮变化**：引用更新，说明改变的是哪一条判断依据；或说明坚持为何合理。
3. **本题主维度评分**：初判与更新分开标注；更新属于有提示表现。若无法判断，记“证据不足”。
4. **下一次试着做到**：只给一条可执行建议。

不重复完整商业分析，不输出标准答案式报告。若用户希望深挖，在训练完成后展开，深挖内容不计作独立表现。

## 5. 训练内容与评分

### 5.1 四个训练维度

| 维度 | 核心观察 | 题目示例 |
| --- | --- | --- |
| 商业逻辑 | 谁付钱、为何付钱、替代方案是什么 | 有人使用的功能是否值得收费 |
| 成本 | 哪项成本随客户或交付规模变化 | 人工服务是否吃掉软件利润 |
| 风险 | 哪个假设会推翻结论，如何验证 | 客户说喜欢是否意味着愿意付费 |
| 利润 | 收入与成本口径一致，能判断盈亏条件 | 月收入增长是否带来实际盈利 |

每题只指定一个主维度。其他维度可以自然出现，不全部评分。不要求用户每次完整覆盖四项。

### 5.2 主维度评分锚点

| 分数 | 可观察表现 |
| --- | --- |
| 0 | 在题目信息足够的前提下，未涉及目标变量或存在关键错误 |
| 1 | 提到了变量，但没有解释它如何影响选择 |
| 2 | 建立基本因果关系，或完成核心数量估算 |
| 3 | 说明关键假设或边界，并据此支持选择 |
| 4 | 检查主要替代解释或敏感条件，给出与证据相称的判断 |

这些是反馈锚点，不是经过验证的能力量表。每个分数需引用原文；允许多种合理结论。若题目缺数据或答案太短无法评估，使用 null 并说明原因，不能简单判 0 分。

成本题不因没有写“付费者”扣分；商业逻辑题不因没有利润区间扣分。挑战后是否更新单独描述，不纳入所有维度的共同最高分要求。

### 5.3 能力等级

阶段复盘保留以下描述：

| 等级 | 证据标准 |
| --- | --- |
| L0 直觉判断 | 表达选择，但很少说明成立条件 |
| L1 提示下识别 | 经提示后能识别重要变量并解释 |
| L2 独立分析 | 新题初判中主动使用重要变量 |
| L3 假设驱动 | 主动说明关键边界、证据缺口和验证办法 |
| L4 结构迁移 | 多个不同情境中无提示使用相同底层关系 |

先对已观察的能力给暂定等级，不强行给全局综合等级。例如：“成本判断暂定 L2，依据两次独立初判；其他维度证据不足。”

由 Skill 在用户请求复盘时生成，不建立升级脚本，不取平均分换算等级。记录不足、不同行为冲突或仍依赖提示时，明确保留不确定性。

## 6. 案例设计

### 6.1 初始案例包

先制作四道题：

| ID | 主维度 | 训练内容 | 用途 |
| --- | --- | --- | --- |
| case_001 | 成本 | AI 服务中的人工交付成本 | 基础练习 |
| case_002 | 商业逻辑 | 使用意愿与付费意愿 | 基础练习 |
| case_003 | 利润 | 收入、获客费用与盈亏边界 | 基础练习 |
| case_004 | 成本 | 不同软件服务中的实施和维护成本 | case_001 的变式复测 |

这是启动包，不声称覆盖全部能力。风险专练及跨行业变式在首轮反馈后补充。样本量不足以支撑长期“每日”供给；持续使用前按实际训练消耗补题，不先建设内容生产平台。

### 6.2 题目类型

- **教学模拟**：数字与情境用于训练，明确标注。
- **真实材料改编**：附来源，明确已知事实与教学假设。

真实结局可选。外部来源只有实际核实后才标“已核实”；无法核实的信息保留为未知，不捏造出处和经营结果。

### 6.3 最小文件结构

每题一个目录：

```text
cases/case_001/
  brief.md       # 只含用户可见题目
  coach.md       # 主维度、关键关系、参考推理、来源与教学假设
  outcome.md     # 可选真实结局
```

brief.md 包含题目类型、背景、已知数据、未知信息和决策问题。coach.md 不给唯一投资结论，而是列出成立条件和可接受的不同推理。

另用一个小型 cases/index.json 记录 id、title、primary_dimension、role、transfer_of 与顺序。结构标签与主维度不在复测题面展示。

### 6.4 上下文边界

- 出题只读 brief.md。
- 用户提交初判后再读 coach.md。
- 保存评分后才允许读取 outcome.md。
- 不通过扫描整个案例目录一次性加载全部文件。

文件拆分降低意外读取，不是安全隔离。模型可能已从训练数据知道知名案例结局；需要减少这类影响时，优先使用不知名案例或明确标注的匿名教学改编。若之后需要严格隔离，再引入受限读取工具，不在 MVP 中承诺模型完全不知道结局。

### 6.5 人工验收清单

每题发布前检查：有真实取舍、信息足以粗判、数字单位一致、只有一个主目标、事实与假设区分、没有在题面暗示答案。变式题还要确认表面情境不同但关键关系一致，且未额外依赖大量行业知识。

## 7. 一个 Skill 的职责与边界

入口名称：business-judgment-practice。

同一 Skill 支持三种自然语言操作：

| 用户意图 | 行为 |
| --- | --- |
| “开始今天的练习”或指定题目 | 启动训练 |
| “继续上次练习” | 读取未完成记录并从下一步继续 |
| “复盘最近的训练” | 汇总表现、证据、暂定等级和一个后续重点 |

案例制作先按参考模板人工完成，不实现独立策展入口。Skill 内保留流程与行为规则，参考文件保存 rubric、案例模板和复盘格式。

使用 Codex 当前会话的推理能力，不增加独立 LLM SDK、runner、服务端、Web UI 或模型路由。此文档中的入口和脚本为待实现设计，并非已安装功能。

Skill 需要明确的停止点：给出题目后等待用户；给出挑战后等待用户。不得模拟用户初判和更新，不得自行完成整轮对话。

## 8. 文件与记录

建议项目结构：

```text
business-judgment-trainer/
  README.md
  .codex/skills/business-judgment-practice/
    SKILL.md
    references/
      rubric.md
      case-template.md
      review-template.md
  cases/
    index.json
    case_001/
      brief.md
      coach.md
  sessions/
  scripts/                 # 出现保存摩擦后再添加
    save_session.py
```

第一版以 JSON 保存一题一份记录，避免 Markdown 原文再转换造成歧义。用户在 GUI 中看到自然语言，不接触内部字段。

### 8.1 Session 最小结构

```json
{
  "id": "session_20260910_001",
  "case_id": "case_001",
  "case_revision": "v1",
  "started_at": "2026-09-10T10:00:00Z",
  "completed_at": null,
  "stage": "awaiting_initial",
  "mode": "practice",
  "prompt_level": "basic",
  "initial_raw": null,
  "challenge": null,
  "updated_raw": null,
  "feedback": null,
  "transfer_from_session_id": null,
  "outcome_revealed": false,
  "rubric_version": "v1"
}
```

challenge 非空时包含 text、target_assumption 与简短 reason。feedback 包含 primary_dimension、initial_score、updated_score、evidence、update_assessment 和 next_focus。evidence 保存引用原文及解释；分数允许 null。

stage 只用于续练定位：awaiting_initial、awaiting_update、completed。没有值得挑战的问题时，记录跳过理由，直接完成。用户暂时离开保持当前阶段，不需要超时任务。

若训练期间获得额外提示，把 prompt_level 更新为 assisted，并记录实际提示文本。复测模式默认为 open。

model 信息可在环境可靠提供时记录；不可获取就省略或写 unknown，不猜测。题目与 rubric 更新时保留版本，以免历史评分失去解释基础。

### 8.2 保存与恢复

- 出题后建立记录；初判后保存原文与挑战；结束后保存更新与反馈。
- 原文不被润色版覆盖，纠错或补充单独追加说明。
- 同一训练重复保存更新同一文件，不新增重复完成记录。
- 保存失败时说明失败并保留当前内容供重试，不声称已保存。
- 存在一个未完成训练时，默认继续；多个未完成时显示题名让用户选。
- 复盘读取已完成记录；未完成训练不计作学习表现。

第一阶段可直接写文件，保存后检查 JSON 可读和关键原文完整。重复操作开始出错后，再实现一个小型 save_session.py：结构检查、同目录临时文件写入、原子替换。不为此建立通用存储层或数据库。

Session 是事实来源。课程进度和暂定等级按需从记录推导；历史量大时先缩小复盘范围，再考虑可重建索引。

## 9. 选题和延迟复测

初版选题规则：

1. 用户明确指定题目时，遵从指定。
2. 有未完成训练时，优先续练。
3. 存在已关联变式，且原训练后至少间隔一次其他训练、跨过一个自然日时，优先变式。
4. 否则按 index 顺序选择未做基础题。
5. 无新题时说明情况，允许重练；重练明确标记，不作为陌生题迁移证据。

第三条是低成本默认安排，不是经验证的最佳学习间隔。不使用定时器，不要求第 7 天精确触发；用户下次打开时检查。若要检验更长保留效果，再手工安排约一周后的题。

变式反馈必须比较原训练与本题初判：是否主动识别目标变量、是否解释它如何影响选择、是否需要提示。先保存无提示初判及判定，再给教学反馈；之后的改进不倒算为无提示表现。

一次成功记为学习迹象，多次不同情境重复出现后再提高能力判断的把握。同领域稳定后再尝试跨行业，行业知识不足与结构遗漏分开说明。

## 10. 交互示例

以下为教学模拟，数字不对应真实企业。

**题面**

你准备销售一项 AI 报告服务，每客户每月收费 500 元，预计 20 个客户。每客户每月模型和工具费用 50 元，人工处理 3 小时；你的时间按每小时 150 元估算。暂不考虑其他固定费用和获客成本。你会直接推广、小规模试卖，还是放弃？请说明依据。

**用户初判**

“先推广，月收入一万元，工具费一千，剩下九千，感觉不错。”

**挑战**

“你说‘剩下九千’，这里尚未扣除你的时间成本。按题目工时计算，这项服务每月需要你投入多少时间？把这部分算进去后，你还会直接推广吗？”

**用户更新**

“要花 60 小时，按时薪折算是九千元，剩余为零，而且还没算获客。我先试卖，看能否把每客户工时降低。”

**反馈**

“你初判已经算了收入和工具费，但没有把交付时间纳入。更新后，你识别出 60 小时对应 9,000 元时间成本，并改变了推进方式。成本判断：初判 1/4，更新 3/4（经提示）。这里的 9,000 元是计入自有劳动前的现金结余；按给定时薪计入劳动成本后剩余为零，不能混用两种口径。下次先检查：客户增长时，哪些工作量也会同步增长？”

这道题不因用户选择推广而直接判错；若用户能解释短期现金需求、时间机会成本和约束，也可能有合理依据。

## 11. 实施步骤与验收

### 阶段 A：跑通真实训练

**任务 A1：写核心 Skill 与参考文件**

产物：SKILL.md、评分规则、案例模板、复盘模板。

验收：出题和挑战后确实停下来等待；不替用户回答；不会提前展示教练备注和结局。

**任务 A2：制作四题启动包**

产物：index.json、四道 brief 与 coach；真实结局按需添加。

验收：人工检查数字、主目标和事实标记；变式不泄露原题提示。

**任务 A3：实现训练记录与续练**

产物：可读取的 Session 文件，初判、挑战和更新原文完整保存。

验收：中途离开后可以继续；已完成记录可复盘；重复保存不重复计数。

**任务 A4：实际使用并观察**

先做约 3–5 次体验检查，不将次数设为功能扩建门槛。重点检查是否能在约 15 分钟内完成、挑战是否具体、反馈是否可由原文解释。

遇到泛泛挑战先改题面与规则；用户忙时保留暂停能力，不靠增加问卷解决。

**任务 A5：完成一次延迟变式与阶段复盘**

产物：原训练与变式初判对照，暂定能力描述和一个后续训练重点。

验收：能够区分“经提示会答”与“主动识别”；没有迹象时如实报告，不用总分上升代替。

### 阶段 B：按实际摩擦补工具

只有出现对应问题才实施：

| 实际问题 | 最小实现 |
| --- | --- |
| 保存出错、重复记录 | save_session.py，结构校验和原子替换 |
| 选题反复出错或耗时明显 | 小型选题脚本，执行已验证规则 |
| 历史过多导致复盘缓慢 | 按日期和维度过滤，必要时可重建索引 |
| 题目供给成为瓶颈 | 完善策展操作；独立使用需求明确后再拆 Skill |
| 评分频繁出现实质争议 | 收集真实争议答案，修订锚点并做小型回归 |

不按“完成若干次”自动增加脚本、等级系统或多个 Skill。

## 12. 必要验证

不建设通用 Eval 平台。先用少量人工对话检查具体风险：

- 完整训练：初判前不透露分析；最多一个实质挑战。
- 合理坚持：用户用证据反驳挑战时，AI 能认可。
- 无须挑战：用户已有完整依据时，不强行挑错。
- 信息不足：不捏造数字，不把无法判断记为错误。
- 中断恢复：原回答保留，继续正确阶段。
- 变式复测：无提示初判与之后教学表现分开。
- 可选结局：反馈保存前没有读取 outcome.md。

保存脚本落地后只补直接相关测试：无效记录不覆盖已有文件、同一 id 重写不产生重复、写入失败保留旧文件。评分有实际争议后再保存典型答案作回归样本，不提前堆积大量 golden answers。

## 13. 成效判断与调整规则

前期逐条看证据，不计算少量样本下的精确迁移率。阶段复盘回答：

1. 哪次挑战指出了原回答里可验证的遗漏？
2. 用户是否改变了因果解释、数量估算或行动条件，而非只是复述 AI？
3. 后续初判是否主动使用该变量？
4. 还在哪些情况下依赖提示？

可选询问一句：“这次最有帮助或最没用的地方是什么？”不增加满意度问卷。

若挑战持续有效、变式出现主动应用且使用负担可接受，就继续补题。若只会复述，减少提示并检查变式设计；若挑战泛化，改案例与挑战规则；若分数争议大，先修评分解释。若长期只有案例知识价值而没有判断改善，需要重新评估训练定位，不能仅凭一两次失败宣布方向无效。

## 14. 完成定义

本版实现完成意味着：

- 一个 Skill 能在 Codex GUI 中完成真实多轮训练，关键位置等待用户。
- 四道启动题可用，其中一道支持延迟变式。
- 初判、挑战、更新、分数及证据可保存和续读。
- 单题只评主维度，阶段等级有证据或明确标注不足。
- 至少走通一次基础练习、一次续练和一次变式复盘。
- 能用记录回答“用户学会了什么、还不能确认什么”。

本版首先交付可使用、可观察、可调整的训练闭环；自动化和能力测量体系依据后续使用证据逐步补充。
