# Quinn 周期性回看开发实施计划

日期：2026-09-24  
状态：待实施。基于《Quinn 实现方案 v3：以理解变化为核心的跨领域探索》；尚未检查仓库，以下路径与接口是逻辑建议，实施时先映射现有文件。

## 1. 目标与边界

借鉴《设计你最好的一年》的“回顾成果与失望 → 提炼学习和限制 → 澄清重视什么 → 选择重点 → 回访”顺序，让 Quinn 帮用户从多次探索中辨认真实的理解变化与下一阶段值得追的问题。

周期性回看是 **quinn-synthesize 的一种按需使用方式**，不是新的年度规划主流程。用户可要求回看最近一个月、一个季度或一年；默认先回看最近三个月，且在回答中明确覆盖的实际日期。任何日期范围均可按用户输入调整，不依赖年初。

完成一次回看，用户应能看到：有出处的历史事实、值得修正的旧判断、真正仍未解决的问题，以及由自己确认的下一阶段关注点。允许结论为“证据不足”“原判断仍成立”“暂时没有重点”。

不在首版创建第四个 Skill、后台提醒、目标打分、十个必填目标、人格画像、人生角色数据库或自动生成的人生计划。不把 Quinn 自己提出的假设写成用户确认的决定。涉及健康、财务、家庭等会话记录未覆盖的领域，明确缺口并由用户选择是否补充。

## 2. 与现有设计的接口

| 现有组件 | 增加的职责 | 保持的边界 |
| --- | --- | --- |
| quinn-synthesize | 按日期和主题检索相关会话；提取可追溯观察；生成待确认的回看；保存用户确认的结论和继续位置 | 不自行推断用户价值观、成就或稳定性格 |
| quinn-explore | 针对一处重要取舍讨论前提、替代解释、尺度变化和下一阶段方向 | 不强制使用框架算子、评分或目标设定 |
| quinn-research | 仅在某个判断依赖外部可核实事实时查证 | 不为了完成年度复盘而全面搜索 |
| workspace/sessions | 作为过去探索的证据入口，记录原问题、观点归属、证据和理解变化 | 不将 AI 候选总结提升为用户观点 |

复用 v3 的会话记录及安全写入机制。若仓库目前尚无对应能力，先完成原计划 P0/P1 的最低依赖；本计划不另建存储层或流程引擎。

## 3. 用户交互

### 3.1 入口

- “回看过去三个月，我在哪些问题上改变了想法？”
- “帮我做季度回看，找出下一阶段最值得想的问题。”
- “根据已有讨论，设计我接下来一年的探索方向。”
- “只回顾 Quinn 的跨领域探索，不讨论其他生活目标。”

如果用户只要总结，输出总结即可。用户要求规划或取舍时才进入后续讨论。时间范围不明确时采用最近三个月并注明；主题存在明显歧义时只问一个澄清问题。

### 3.2 一次回看的最小流程

1. **确定范围**：时间、主题、可用记录数量和明显缺口。先通过日期与主题筛选，仅读候选相关会话的完整内容，不把检索片段当证据。
2. **展示过去**：用少量有会话引用的观察归纳实际探索、成果、失望或未完成尝试；“没有记录”只能写成覆盖缺口。
3. **检查解释**：挑出 1—2 个反复出现的判断或卡点，列出支持、反例和不确定性。自我设限只能作为待讨论的假设，不能进行心理诊断。
4. **邀请用户修正**：先给简短候选回看，再问一个最能改变结论的问题。用户可以纠正事实、拒绝归纳、补充记录外信息、只看总结或跳过。
5. **讨论取舍**：用户想定方向时，用 explore 比较最多 2—3 个实质不同的方向：各自回应什么问题、依赖什么条件、放弃什么、什么证据可能改变选择。
6. **沉淀与回访**：保存用户已经确认的关注点、仍待验证的判断和下次回访信号；没有确认则保存为 Quinn 候选，不制造决定。

避免把十个问题连续展示成问卷。原书问题作为内部覆盖检查：成果、失望、学习、限制、价值/角色、重点、推进。用户没有要求全面人生规划时，角色与价值只围绕当前讨论涉及的范围。

### 3.3 默认输出

```text
回看范围：2026-07-01 至 2026-09-30；参考 N 次相关讨论

过去确实发生了什么：2—3 条，分别附会话日期/ID
值得重新检查的判断：1—2 条，区分用户原话与 Quinn 的解读
当前开放的问题：不超过 3 条
下一阶段方向：仅当用户希望讨论，列出候选和取舍；确认后标记“用户选择”
回访条件：出现何种新证据、尝试结果或时间节点时再看
覆盖缺口：哪些信息未进入 Quinn 的记录
```

根据内容自然缩短输出，不为填满格式重复文字。首次展示不直接宣称“你的年度目标是……”。

## 4. 数据与归属

首版在现有会话体系中保存一份回看记录，可逻辑表示为 `review` 类型；若现有 schema 不支持类型，使用一份普通 Markdown 会话并标注回看范围。不引入独立数据库或强制迁移旧文件。

| 字段 | 作用 |
| --- | --- |
| review_id、period_start、period_end、topics | 标识范围与恢复位置 |
| source_session_ids | 可追溯的输入会话 |
| observations | 各条观察及对应会话依据、Quinn 的推断程度 |
| corrections | 用户对观察的补充或纠正，保留原文 |
| candidate_directions | Quinn 提议，默认不等于用户目标 |
| user_confirmed_focus | 仅记录用户明确确认的方向和范围 |
| open_questions、revisit_when | 未知与回访条件，可为空 |
| status、updated_at | draft / discussed / closed；状态不表示结论正确 |

有用的新反馈以追加修订形式更新同一回看，保留用户原话及先前版本。记录与已引用的会话之间使用稳定 ID；重复运行同一范围与主题时优先更新或并列新版本，不静默复制成多个“定论”。写入冲突和失败沿用 v3 的处理规则。

来源分三类显示：**已有记录中的用户表达**、**外部材料或真实行动的可核查事实**、**Quinn 的候选解释**。用户后来纠正事实时修订回看结论，不篡改原会话。

## 5. 开发任务

### P0：仓库核查与设计映射

- [ ] 读取 AGENTS.md、现有 Skill 入口、会话存储和恢复方式、相关测试。
- [ ] 核对 v3 已实现与待实现项；确认回看可复用的实际文件、函数和字段。
- [ ] 选取一组真实且允许使用的会话记录，核查日期、观点归属与引用能力；记录基线输出。
- [ ] 确定旧记录缺字段的读取策略；没有用户原话时不反向推断立场。

验收：得到实际改动清单和一组可重演样本；不声称计划中的接口已经存在。

### P1：按需回看 MVP

- [ ] 在 synthesize 指引加入“按周期回看”的触发、范围选择、证据归属、缺口说明和精简输出。
- [ ] 实现或复用按时间/主题找候选记录并读取完整会话的最小检索；无需全量载入。
- [ ] 将“过去发生了什么”和“Quinn 如何解释”分开；限制首轮观察条数。
- [ ] 在 explore 指引加入围绕一处取舍的讨论；由用户选择是否进入下一阶段规划。
- [ ] 复用现有写入方式保存回看、用户纠正和待确认候选；失败时明确告知。

验收：从真实会话生成一份可追溯的三个月回看；无记录时准确报告缺口；用户拒绝归纳后不留下“已确认”内容；只要总结时不会追问目标。

### P2：持续回访

- [ ] 按 `review_id` 或主题继续同一回看，展示此前已确认内容和新增材料。
- [ ] 当用户带来行动反馈或新证据时，比较它与原判断的关系；允许判断维持不变。
- [ ] 增加可选的回访条件表达：“出现首个真实用户反馈后再回看”“一个季度后主动向 Quinn 发起回看”。不承诺后台通知。
- [ ] 使用一次跨期真实样本验证旧观察、用户纠正、新证据和最终方向的可追溯性。

验收：再次进入时准确接续；新证据可使方向修订或保持，不会覆盖旧判断；无自动提醒时不会声称已设置提醒。

### P3：根据真实使用反馈扩展

仅在 P1/P2 表明需要时，考虑将季度/年度模板、跨会话索引、提醒或独立 Skill 产品化。依据是回看检索成本、用户是否反复触发以及是否需要更长周期的专门交互；不以 Skill 数量作为完成标准。

## 6. 验收场景

| 场景 | 预期结果 |
| --- | --- |
| 有三个月讨论，用户仅要总结 | 只总结有证据的变化和未知，附会话定位 |
| 讨论记录稀疏，要求“全面人生回顾” | 标出覆盖缺口，邀请用户补充必要领域，不编造 |
| Quinn 提出“你害怕公开表达” | 作为待确认解释或删掉，不记录为用户心理事实 |
| 用户反对某条归纳 | 保存纠正原文并更新回看；不把旧归纳继续当定论 |
| 用户未选择下一阶段方向 | 候选仍为候选，不生成已确认年度目标 |
| 只有一个新事实依赖外部资料 | 仅查证关键事实并标记来源与时效 |
| 重复生成或并发修改回看 | 不重复建档、不静默覆盖用户修订 |
| 用户要求继续一年后回访 | 记录回访条件；若无定时能力，说明需用户再次发起 |

代码测试聚焦检索范围、引用完整性、归属与版本冲突；认知输出使用真实样本人工检查：是否误判成长、是否强行改判、是否提出真正不同的方向、交互是否过重。

## 7. 上线判断

最小可交付版本完成 P0/P1 即可个人试用。成功信号是用户能发现一条此前没看清、且有会话依据的长期模式，或者更准确地修正一条旧解释；随后能说清一个值得继续的问题。一次漂亮的年度计划不构成成功证据。

建议的首次试用提示词：**“Quinn，回看过去三个月关于 Quinn、Finch 和产品方向的讨论。先告诉我哪些判断确实发生了变化、证据在哪，以及哪些只是你推测的；然后陪我选一个下一阶段值得验证的问题。”**
